BLEX 4 기술 구조와 요청 흐름

TypeScript로 작성한 Fastify 서버 한 프로세스가 React 화면과 API, 정적 파일을 제공합니다. 주소로 직접 접속하면 완성된 HTML을 받고, 그 뒤의 내부 이동은 브라우저의 공통 React 라우터가 처리합니다.

요청 흐름

탭을 바꿔 브라우저와 서버가 각각 하는 일을 비교할 수 있습니다.

주소창에서 홈을 연다

브라우저가 새 문서를 요청하는 경우

  1. 브라우저 홈 주소 요청

    GET /를 보내고, 이전에 로그인했다면 세션 쿠키를 같이 보냅니다.

  2. Fastify 홈 핸들러에서 데이터 조회

    페이지 번호를 검사하고 Prisma로 사이트 설정, 공개 글 목록과 전체 글 수를 읽습니다. 세션이 있으면 사용자와 읽지 않은 알림 수를 확인합니다. 공지와 글 카드의 좋아요 정보도 조회합니다.

  3. React SSR 캐시 정책과 메타데이터가 있는 HTML 응답

    PageLayout이 헤더, 최신 글 카드, 푸터, 제목과 canonical을 담아 200 text/html로 보냅니다. 로그인한 사용자의 HTML에는 private, no-store가 적용됩니다.

  4. 브라우저 먼저 표시하고 공통 라우터 연결

    받은 글 목록을 바로 표시합니다. Vite가 만든 앱 스크립트가 실행되면 hydrateRoot가 SSR 문서에 공통 React 앱을 연결합니다.

브라우저에서 보이는 요청

GET /
  ← 200 text/html
     헤더 · 글 목록 · 메타데이터
GET /assets/blex/app.js
  ← 302 /assets/ui/assets/…
GET /assets/ui/assets/…
  ← Vite가 빌드한 앱 JavaScript

검색엔진도 첫 HTML에서 본문과 메타데이터를 읽을 수 있습니다. 글 주소에는 본문과 공개 글의 BlogPosting JSON-LD도 들어갑니다.

관련 코드 홈 라우트 · SSR 문서

홈에서 글 제목을 누른다

앱을 실행 중인 브라우저에서 내부 링크를 누르는 경우

  1. React Router 같은 출처의 링크 처리

    공통 앱이 클릭을 받아 fetch로 글 주소의 HTML을 요청합니다.

  2. Fastify 글 상세를 서버에서 렌더링

    직접 주소를 열 때와 같은 /@:username/:slug 라우트입니다. 글을 볼 수 있는지 검사하고 상세 HTML을 만듭니다.

  3. 브라우저 주소, 본문, 메타데이터 교체

    ApplicationFrame이 응답 HTML에서 본문을 표시하고 라우터가 제목과 canonical 등을 갱신합니다. 현재 브라우저 문서와 공통 헤더가 이어서 사용됩니다.

  4. 브라우저 스크롤과 화면 도구 연결

    새 글은 처음 위치에서 열리고 뒤로 가면 저장해 둔 위치로 바로 돌아갑니다. 로그인 폼과 글 편집기는 해당 화면에서 React 모듈을 로드합니다.

같은 문서 안에서 바뀌는 부분

링크 클릭
  → fetch GET /@writer/hello
  ← 200 text/html
     제목 · canonical · 글 본문
  → 본문 교체 · 주소 갱신
  → 뒤로 가기 위치 저장 및 복원

공통 React 앱이 서버에서 만든 화면 HTML을 라우트별로 가져옵니다. 공통 헤더는 React 컴포넌트이고, 화면 본문은 SSR HTML입니다.

관련 코드 라우터와 로더 · 공통 화면

계정 설정에서 표시 이름을 저장한다

브라우저가 폼을 보내고 서버 결과를 같은 앱에서 표시하는 경우

  1. 브라우저 폼 데이터를 POST

    공통 앱이 폼 값을 모아 POST /settings/account로 보냅니다. 요청에는 세션 쿠키와 CSRF 토큰이 포함됩니다.

  2. Fastify 요청과 데이터 검사

    세션과 CSRF를 검사하고, intent=name에 맞춰 표시 이름을 검증합니다. Prisma로 해당 계정의 값을 저장합니다.

  3. Fastify 저장된 화면 주소 반환

    성공하면 303으로 /settings/account?saved=1을 안내합니다. 입력이 유효하지 않으면 오류를 담은 설정 화면 HTML을 반환합니다.

  4. React Router 결과 화면 반영

    브라우저의 요청이 이동 주소를 따라가 최종 HTML을 받습니다. 공통 라우터가 그 결과를 현재 앱에 표시합니다.

성공했을 때의 요청과 응답

POST /settings/account
  intent=name · name=…
  ← 303 See Other
GET /settings/account?saved=1
  ← 200 text/html
     변경된 표시 이름 · 저장 안내

로그인과 쓰기 권한은 서버에서 검사합니다. 관리자 설정도 같은 Fastify 서버와 React 화면을 사용합니다.

관련 코드 계정 저장 · 세션 조회

기술 스택

현재 packages/server 프로젝트 기준입니다. 의존성 잠금 파일

언어 · 런타임

TypeScript 6 · Node.js 24

서버와 웹 앱을 TypeScript로 작성합니다. 서비스는 Node 프로세스로 실행됩니다.

서버 · API

Fastify 5

SSR 페이지, 폼과 기존 HTTP API를 제공합니다.

화면 · 라우팅

React 19 · React Router 7

같은 React 화면을 서버에서 렌더링하고, 브라우저의 공통 앱이 내부 이동을 처리합니다.

빌드 · 편집기

Vite 7 · Tailwind CSS 4 · Tiptap 3

Vite가 브라우저 자산을 빌드합니다. Sass로 화면 스타일을 보완하고, Tiptap은 글쓰기 화면에서 로드합니다.

데이터 · 스키마

Prisma 6 · SQLite

SQLite 파일을 사용합니다. Prisma가 스키마 변경을 관리하고, 일부 기존 테이블은 파라미터 바인딩 SQL로 읽고 씁니다.

배포 · 미디어

Docker · Sharp · FFmpeg

서비스 이미지는 Node 기반입니다. SQLite 파일과 업로드 디렉터리를 마운트하고 이미지·영상 처리를 같은 서비스에서 실행합니다.

설치와 운영 자체 호스팅 가이드에서 실행과 백업을, 이전 가이드에서 기존 DB와 미디어를 옮기는 절차를 확인할 수 있습니다.
