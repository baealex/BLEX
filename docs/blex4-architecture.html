BLEX 4 Architecture and Request Flows

A single Fastify server, written in TypeScript, serves React pages, APIs, and static files. When a visitor opens a URL directly, the server returns rendered HTML. The shared React router handles subsequent internal navigation.

Request flows

Switch tabs to compare the work done by the browser and server.

Open the home page directly

The browser requests a new document

  1. Browser Request the home URL

    The browser sends GET / and includes a session cookie if the visitor is signed in.

  2. Fastify Load data in the home handler

    The handler validates the page number and uses Prisma to load site settings, public posts, and the total post count. For signed-in visitors, it also loads the viewer and unread notification count. Other page data includes notices and like information for post cards.

  3. React SSR Return HTML with cache policy and metadata

    PageLayout renders the header, latest post cards, footer, title, and canonical URL. The server sends a 200 text/html response and sets Cache-Control to private, no-store for signed-in visitors.

  4. Browser Display the page and connect the router

    The browser displays the post list immediately. When the app script built by Vite runs, hydrateRoot connects the shared React app to the SSR document.

Click a post title on the home page

The running app handles an internal link

  1. React Router Handle a same-origin link

    The shared app handles the click and uses fetch to request the post HTML.

  2. Fastify Render the post on the server

    The server uses the same /@:username/:slug route as a direct visit. It checks whether the visitor can view the post, then renders the HTML.

  3. Browser Update the URL, content, and metadata

    ApplicationFrame displays content from the returned HTML, while the router updates the title and canonical URL. The browser document and shared header stay in place.

  4. Browser Restore scroll and initialize interactions

    Opening a different post scrolls to the top. Going back restores the saved scroll position. Login forms and post editors load their React modules on the relevant screen.

The shared React app fetches server-rendered HTML for each route. The shared header is a React component; page content is SSR HTML.

Save a display name in account settings

The browser submits a form and displays the result in the same app

  1. Browser POST the form data

    The shared app collects form values and sends POST /settings/account with the session cookie and CSRF token.

  2. Fastify Validate the request and data

    The server validates the session and CSRF token. For intent=name, it validates the display name and saves it using Prisma.

  3. Fastify Redirect to the updated page

    After saving, the server sends a 303 redirect to /settings/account?saved=1. If validation fails, it returns the settings page with an error message.

  4. React Router Display the result

    The browser follows the redirect and receives the final HTML. The shared router displays it in the current app.

Successful request and response

POST /settings/account
  intent=name · name=…
  ← 303 See Other
GET /settings/account?saved=1
  ← 200 text/html
     Updated display name · confirmation

The server checks authentication and write permissions. Administrator settings use the same Fastify server and React screens.

Technology stack

Versions used by packages/server. Dependency lockfile

Language · runtime

TypeScript 6 · Node.js 24

The server and web app use TypeScript. The service runs as a Node process.

Server · APIs

Fastify 5

Serves SSR pages, forms, and existing HTTP APIs.

Screens · routing

React 19 · React Router 7

React renders pages on the server; the shared browser app handles internal navigation.

Build · editor

Vite 7 · Tailwind CSS 4 · Tiptap 3

Vite builds browser assets. Sass handles additional styles, and Tiptap loads on the writing screen.

Data · schema

Prisma 6 · SQLite

Data is stored in SQLite. Prisma manages schema changes, and parameterized SQL is used to read and update some existing tables.

Deployment · media

Docker · Sharp · FFmpeg

The runtime image uses Node. It mounts the SQLite file and upload directory and processes images and video within the same service.

Installation and operations The self-hosting guide covers running and backing up an instance; the upgrade guide covers moving an existing database and media directory.
